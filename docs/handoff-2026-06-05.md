# PARTE 1 — INVESTIGACIÓN: cómo resolver el coloquial

## El problema, en una frase
Cuando el usuario pregunta en lenguaje cotidiano ("se me corta la luz, ¿quién controla?") en vez de
legal ("¿qué organismo fiscaliza la continuidad del suministro?"), el retrieval no trae el artículo
correcto: la frase cotidiana y el texto legal caen LEJOS en el espacio de embeddings. Es una brecha
de **registro** (cotidiano↔legal), no de vocabulario suelto ni de capacidad del LLM.

## Diagnóstico cuantificado (set `queries_coloquial_v2.jsonl`, 39q diversas, gold de la ley)
- **Baseline: gold∈top10 = 28/39 (72%)** (coincide con 8/11 de v3 → número confiable).
- El residual (~28%) se parte en:
  - **near-miss** (rank 12-17, ~15%): el gold está apenas debajo del corte.
  - **deep-miss** (None en top-50, ~13%): el gold ni aparece.

## Qué se probó y NO alcanzó (mapa completo, con evidencia)
| familia | levers | resultado |
|---|---|---|
| **embedder** | bge-m3 (mismo tamaño que Qwen3-0.6B) | coloquial 5/11=igual, −2 neto. Qwen3-4B/8B NO entran (8GB GPU / 14GB RAM) |
| **reranker / late-interaction** | BGE cross-encoder pool@50/100/200, ColBERT (bge-m3 multi-vector) | nulo (8/11) / peor (7/11). Ningún scorer sube el gold profundo aunque lo vea |
| **doc-side** | term-prefix glosario, Contextual Retrieval (Anthropic) | rechazado / no rescata |
| **query-side genérico** | HyDE, multi-query, step-back, decomposición, #6 intent-extraction | +1 marginal o wash; #6 driftó (alucinó "NCh 1082") |
| **top_k** | 10→20 | coloquial +3 PERO dev −2 (dispersión). Trade-off, no global |
| **gate semántico** (adoptado) | bge_max<τ | arregla el RECHAZO de coloquial, no el retrieval |

## EL HALLAZGO que SÍ funciona (2026-06-05): reformulación SELECTIVA
**`scripts/exp_selective_reform.py`** — un call LLM condicional que reescribe la query cotidiana a
lenguaje legal formal (restatement completo), **aditivo** (conserva la query original en BM25+vector).
- **Retrieval: coloquial gold∈top10 28→34/39 (+6); dev 12→12 (CERO regresión).**
- Rescató deep-miss que nada antes movió (acceso abierto None→7, facturación None→9, tope paneles None→4).

**Por qué funciona donde #6/HyDE no** (clave para la próxima sesión):
- Hace **restatement formal completo** (Query2Doc + register-shift), NO "extraer el término" → no
  inventa especificidades erradas (el drift de #6).
- Es **aditivo** → las queries ya-legales conservan su señal (por eso dev no regresa, aunque el LLM
  también las "reformula": el restatement formal de una query ya-formal es casi idéntico).
- Es el **estándar 2025**: PreQRAG (SIGIR LiveRAG, clasificar+reescribir selectivo), "Not All Queries
  Need Rewriting", patrón legal "reemplazar variante coloquial por término de vocabulario controlado".

**Quedan 3 deep-miss que ni la reformulación rescata** (tope ganancia→118, panel financiamiento→212,
oficina-reclamo→202975/76): el restatement no acierta el término legal EXACTO. Necesitan entity/concept
anchoring (grafo) o un embedder que entienda el mapeo (fine-tune).

## Caveat pendiente de cerrar
El +6 es **retrieval (gold∈top10)**. FALTA confirmar que convierte a **cita_ok** en generación y que
no regresa dev/holdout/extremo a nivel de generación. Ese es el primer paso del experimento largo.

## FASE A — Confirmar y adoptar la reformulación selectiva (prioridad 1, ~2-3h)

   - En `SimpleRetriever._search_text` (y/o ComplexRetriever): si el flag está ON, `vec_text = query + " " + reform`
     (aditivo, vector-only; BM25 queda con la query original — como `hyde_in_simple`).
2. **Medir generación completa** (Ollama 9b, ~1.5h): cita_ok + grounding sobre

3. **Criterio de éxito**: coloquial cita_ok sube ≥ +4 y dev/holdout NO bajan (±1 = ruido Ollama).

   - Si el +6 de retrieval NO convierte a cita_ok (el LLM no cita el gold aunque esté en top-10) →
     es el cuello de GENERACIÓN ya conocido (elección de cita), no retrieval → registrar y pasar a B.

## FASE B — Los 3 deep-miss restantes: entity/concept anchoring (~2h)
Cuando la query nombra/implica un organismo o concepto ("quién controla/fiscaliza/sanciona" → SEC;
"quién resuelve discrepancias" → Panel), linkear a la entidad y BOOST/inyectar su artículo. Ya existe
infra: grafo de conceptos + `define_termino` + `find_subject_concept` + `inject_definition`.
1. Detectar entidad legal en la query (puede ser el MISMO restatement de Fase A: extrae "Superintendencia").
2. Mapear entidad→artículo canónico (grafo/curado) → inyectar (score 9999) como `inject_definition`.
3. Medir en los 3 duros + no-regresión. Flag-gated.
OJO: es más "específico" (reglas/grafo) — medir overfit en held-out.

## FASE C — El camino de fondo (ambicioso, overnight): fine-tune embedder chileno
La similitud genérica NO cruza el registro; el fix de raíz es un embedder que SÍ. Nuevo: **ya tenemos
el material de entrenamiento** — los pares (coloquial → restatement legal) que genera la Fase A son un
dataset contrastivo listo.
1. **Generar dataset** (Ollama, offline, ~varias h): para cada artículo/concepto, N preguntas coloquiales
   (como se generó coloquial_v2 pero a escala) + su artículo gold = pares (query_coloquial, artículo).
   Held-out REAL = `queries_coloquial_v2` (nunca en train).
2. **Fine-tune** `dccuchile/tulio-chilean-spanish-bert` (BERT chileno, 110M, entra en la 1080) o
   `Qwen3-Embedding-0.6B` como sentence-transformer con MultipleNegativesRankingLoss (~30-60min GPU).
   OJO: Tulio es 768-dim → migrar columna pgvector (1024→768) o usar el Qwen 0.6B (1024, drop-in).
3. **Evaluar** fine-tuned vs Qwen base sobre coloquial_v2 held-out + no-regresión dev/holdout/extremo.
   Riesgo: overfit al estilo sintético → por eso el held-out de gold-leído-de-la-ley es el juez.
4. Adoptar solo si gana sin regresión.
Caveat honesto (el usuario lo marcó): es solución ESPECÍFICA; medirla con held-out honesto es obligatorio.
